# Decisions

Read this before changing the code. It records what was decided while architecting the collector, so that a later agent does not re-derive or quietly undo it. [initial-specs.md](../initial-specs.md) is the source of truth for behaviour; this file explains how the code realises it and where it differs. [invariants.md](invariants.md) lists the rules that tests enforce. If the spec changes, `telemetry/spec_sync_test.py` fails until a person re-reviews and accepts it (see CLAUDE.md).

## Decided

- **DEC-01 Language and runtime.** Python, standard library only, `requires-python >=3.10` (the spec's floor). No third-party runtime dependency, so a hook process starts fast and the collector can be shipped as a small package or zipapp. Ruff is the only dev tool.
- **DEC-02 One package, flat modules.** `telemetry/` holds the modules the spec names (hook, config, uploader, service) plus the ones the design needs: `events` (hook event registry), `schema` (envelope, buckets, bounded vocabularies), `allowlist` (raw hook input to event), `spool` (SQLite), `diagnostics`, `managed_settings`. Dependencies point one way: hook -> allowlist -> schema/events; hook -> spool -> nothing; uploader -> spool. `__init__.py` is empty and imports are absolute (`from telemetry import ...`).
- **DEC-03 Spec deviation: `spool.py`, not `queue.py`.** The spec lists `queue.py`. A file named `queue.py` shadows the standard library `queue` module whenever its directory is on `sys.path`, and a hook launched as a script puts exactly that directory first. The module is `spool.py`; `spec_sync_test.py` records this as a declared deviation.
- **DEC-04 Spec deviation: the hook is launched as a module.** The spec's sketch is `python3 /managed/path/telemetry/hook.py`. For the same shadowing reason, and so `from telemetry import ...` works, the command is `python3 -m telemetry.hook` using the interpreter of an environment where the package is installed (`pip install` into a venv or pipx; the exact managed path is deployment-specific and passed to `managed_settings()`).
- **DEC-05 The hook never fails the session.** `main()` always returns 0 and prints nothing. Every failure becomes a dropped event with a counter (`dropped_invalid`, `dropped_oversize`, `dropped_full`, `dropped_error`) or a redacted line in the diagnostics log (an error class name, never a message).
- **DEC-06 Allowlist, not redaction.** `allowlist.build_event` constructs a new dict field by field. Raw input is only read through named accessors; identifiers must match `[A-Za-z0-9_.:-]{1,128}`; free text (prompt, error) is reduced to a bucket or a bounded class and then discarded. Never add a "pass through the rest" path.
- **DEC-07 Metadata allowlist additions.** The spec's envelope has no place for agent ID, session start source, end reason, batch size or correlation quality, so they live in `metadata` and are listed in `METADATA_FIELDS` with bounded values. Adding a field means changing `METADATA_FIELDS`, `docs/privacy.md` and a privacy review.
- **DEC-08 Correlation quality.** A tool event without a valid `tool_use_id` is still recorded with `tool_use_id` null and `correlation_quality: "none"`; its `event_id` is a local UUID.
- **DEC-09 Durations are not computed in the hook.** `duration_ms` is null at capture. Durations are derived downstream by pairing `PreToolUse` and `PostToolUse` on one host; the spec forbids cross-machine arithmetic.
- **DEC-10 Spool.** SQLite in WAL mode in the user data directory (`~/Library/Application Support/claude-telemetry` on macOS, `$XDG_DATA_HOME/claude-telemetry` elsewhere), directory mode 0700, `PRAGMA user_version` migrations in `spool.MIGRATIONS` (append only, never edit a shipped entry), `event_id` unique so re-delivery is a no-op, a short busy timeout (default 50 ms), and a size cap checked before each insert. Claiming uses a lease (`claimed_until`) so a crashed uploader's rows come back.
- **DEC-11 Local run on macOS.** Service is a launchd LaunchAgent running `python3 -m telemetry.service`; the credential comes from the Keychain through a lookup in the uploader, never from settings or arguments; the prototype ingestion endpoint is a fake server on localhost (config accepts `http://` only for localhost). See [local-architecture.md](../local-architecture.md).
- **DEC-12 Style.** Same rules as the sibling repo ai-factory, enforced by ruff plus `telemetry/style_test.py`: short functions (over 20 lines fails), no comments or docstrings, nesting depth at most 4, pathlib, explicit encodings, no `try`/`except`/`pass`, test files named `<name>_test.py` beside the module. Differences from ai-factory: Python 3.10 target (the spec's floor, ai-factory uses 3.12), extra ruff rules `UP` and `BLE001` (a deliberate blanket `except Exception` carries `# noqa: BLE001`), and an empty-`__init__.py` check.
- **DEC-13 Keeping spec, docs and code in step.** `spec_sync_test.py` parses the spec and checks: the hook event table equals `HOOK_EVENTS`; the excluded events are not registered; the example envelope equals `ENVELOPE_FIELDS` and `SCHEMA_VERSION`; the module tree exists; the settings sample matches `managed_settings()`; the prompt buckets match; the Python floor matches `pyproject.toml`; every invariant has a test and vice versa; every acceptance criterion is covered by an invariant; a hash of the spec (`docs/spec.sha256`) forces a human review when the spec changes. A Claude Code Stop hook in `.claude/settings.json` runs the sync tests when the spec or docs changed.

## Needs verification

- **VER-01 Claude Code hook payload field names. Verified 2026-10-22** against captured key names and types for PreToolUse, PostToolUse, PostToolUseFailure, SubagentStart and SubagentStop (and live spool rows for PermissionDenied). Every field `allowlist.py` reads is present with the expected type; tool events carry `tool_use_id`, so correlation is exact. Real payloads also carry fields the allowlist deliberately ignores (`tool_input`, `tool_response`, `cwd`, `transcript_path`, `last_assistant_message`, `prompt_id`, `effort`). Raw samples were not kept because they contain paths and content.
- **VER-02 Failure class vocabulary. Reviewed 2026-10-22.** A Bash failure error starts `Exit code N` followed by stderr. Keywords now match as patterns, so `generate` no longer reads as `rate_limit` and `author` no longer reads as `auth`. A failure whose stderr names nothing (for example curl's progress meter on exit 7) stays `other`; the exit code is not used.

## Open (from the spec, need an owner)

Ingestion endpoint and owner; identity source and key management; repository identifier policy; supported operating systems and Python distribution; warehouse and dashboard platform; retention, access roles and minimum group size; whether CI outcomes are joined. Until decided, code against the fake endpoint and keep these choices behind `config.py`.

## Local infrastructure

- **DEC-14 Local servers first, cloud later.** Everything runs on the developer's Mac: the spool, the uploader LaunchAgent and a fake ingestion server on `127.0.0.1:8080` (`telemetry/fake_ingest.py`, stores to `~/Library/Application Support/claude-telemetry-ingest/ingested.sqlite`). Moving to cloud means changing `TELEMETRY_ENDPOINT` and the credential source; the uploader's wire contract (POST `{"events": [...]}`, `Authorization: Bearer`, `Idempotency-Key`) is the interface to keep.
- **DEC-15 Credential.** One random token in the Keychain under service `claude-telemetry` (`make token`), read by both the uploader and the fake server through `credential.lookup`. It is never in a plist, setting or argument.
- **DEC-16 Uploader outcomes.** `ok` deletes rows and stamps `last_upload_at`; `retry` (network, 408/425/429/5xx) releases the claim and the service backs off with jitter; `permanent` (other 4xx) deletes the rows and counts them as `rejected`, because the spec forbids retrying them indefinitely.
- **DEC-17 Single uploader and health.** `service.acquire_lease` takes a non-blocking `flock` on `uploader.lock` in the spool directory. Health is `python3 -m telemetry.service --health` (JSON from the spool); there is no listener.
- **DEC-18 launchd.** `python3 -m telemetry.launchd install` writes two LaunchAgents (uploader, fake ingest) and bootstraps them; `uninstall` reverses it. Not run by tests.
- **DEC-19 Context-size reminders.** Two optional, separate mechanisms, trialled side by side to compare them in use: a status line segment (`telemetry/statusline.py`, reads `context_window.total_input_tokens`, passive, no state) and a pair of hooks (`telemetry/context_nudge.py`). The hooks split the work so no prompt waits on a transcript read: an async `Stop` command (`record`) reads the last 256 KB of the transcript and leaves a pending file; a sync `UserPromptSubmit` command (`deliver`) only checks that file and emits `additionalContext` asking Claude to suggest `/mattpocock-skills:handoff`. The sync hook exists because async output never reaches Claude. State is a `seen` and a `pending` integer per session under `<spool dir>/context-nudge/<session>/`, not pruned. Thresholds: 100000, then every 50000, shared in `context_size.py`. None of it is in `telemetry.hook` or `managed_settings()` (INV-24). The transcript usage fields are not a stable contract; recheck them if the hooks go quiet. Open question: whether the team keeps one, both or neither after trying them. A project `statusLine` setting replaces a personal one, so a team rollout should offer the script to call from an existing status line.
